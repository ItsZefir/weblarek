# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной T тип данных, которые могут быть переданы в метод render для отображения.

Конструктор:  
constructor(container: HTMLElement) - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
container: HTMLElement - поле для хранения корневого DOM элемента компонента.

Методы класса:  
render(data?: Partial<T>): HTMLElement - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от Component будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова render и записывать данные в необходимые DOM элементы.  
setImage(element: HTMLImageElement, src: string, alt?: string): void - утилитарный метод для модификации DOM-элементов <img>


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
constructor(baseUrl: string, options: RequestInit = {}) - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
baseUrl: string - базовый адрес сервера  
options: RequestInit - объект с заголовками, которые будут использованы для запросов.

Методы:  
get(uri: string): Promise<object> - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object> - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется POST запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
handleResponse(response: Response): Promise<object> - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
_events: Map<string | RegExp, Set<Function>>) -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
on<T extends object>(event: EventName, callback: (data: T) => void): void - подписка на событие, принимает название события и функцию обработчик.  
emit<T extends object>(event: string, data?: T): void - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Структура данных приложения 

Приложение оперирует двумя ключевыми сущностями: данными о товаре и информации о покупателе.

#### Интерфейс IProduct

Задаёт шаблон данных для описания товара в системе. Используется для отображения информации о продукте, доступном к приобретению. Включает все атрибуты, необходимые для идентификации позиции и предоставления пользователю сведений о её характеристиках, визуальном представлении и стоимости.


Поля интерфейса:
id: string — уникальный идентификатор товара;
title: string — наименование товара, которое отображается в карточках каталога и в корзине;
description: string — развёрнутое описание продукта с подробной информацией о характеристиках;
image: string — путь к файлу изображения товара, используемый для его визуализации в каталоге и карточках;
category: string — категория, к которой принадлежит товар;
price: number | null — стоимость товара в числовом формате. Значение null указывает на отсутствие или недоступность цены.

#### Интерфейс IBuyer

Определяет структуру данных о клиенте приложения. Содержит сведения, требуемые для оформления покупки: способ оплаты, контактные данные и адрес доставки. Это позволяет корректно обрабатывать заказы и поддерживать связь с покупателем.

Поля интерфейса:
payment: TPayment — выбранный метод оплаты. Ограничен набором допустимых значений через тип TPayment;
address: string — адрес для доставки товара, указываемый пользователем при оформлении заказа;
email: string — электронная почта клиента, используемая для отправки уведомлений о заказе и связи с ним;
phone: string — номер телефона покупателя, необходимый для коммуникации по вопросам заказа и доставки.
Тип TPayment

type TPayment = 'card' | 'cash' | '' — объединение типов, задающее допустимые способы оплаты. Гарантирует, что поле payment может принимать только одно из указанных значений.


### Модели данных

#### Класс ProductCatalog

Управляет коллекцией доступных товаров и отслеживает позицию, выбранную для детального просмотра. Предоставляет базовые операции для работы с каталогом.

Конструктор:
constructor() — инициализирует пустой массив для хранения товаров и переменную для выбранного товара (без аргументов).

Поля класса:
protected products: IProduct[] — массив всех товаров в каталоге;
protected selectedProduct: IProduct | null — товар, выбранный для подробного отображения.

Методы:
saveProducts(products: IProduct[]): void — сохраняет переданный массив товаров в модель каталога;
getProducts(): IProduct[] — возвращает полный список товаров из модели;
getProductByID(id: string): IProduct | undefined — ищет и возвращает товар по его идентификатору;
saveProduct(product: IProduct | null): void — сохраняет товар для подробного просмотра;
getProduct(): IProduct | null — возвращает выбранный для отображения товар.

#### Класс ShoppingCart

Хранит перечень товаров, отобранных покупателем для приобретения. Обеспечивает полный набор операций для управления корзиной: просмотр содержимого, добавление и удаление позиций, очистку, подсчёт суммы и количества, проверку наличия товара.

Конструктор:
 constructor() — создаёт пустой массив для хранения выбранных товаров (без аргументов).

Поле класса:
 protected selectedProducts: IProduct[]` — список товаров в корзине покупателя.

Методы:
 getSelectedProducts(): IProduct[] — возвращает все товары, находящиеся в корзине;
 addSelectedProduct(product: IProduct): void — добавляет указанный товар в корзину;
 deleteSelectedProduct(id: string): void — удаляет товар с заданным id из корзины (через фильтрацию);
 clearShoppingCart(): void — очищает корзину, устанавливая пустой массив;
 getTotal(): number` — вычисляет и возвращает общую стоимость товаров в корзине (0 для пустой корзины или при отсутствии цен);
 getSelectedProductsAmount(): number — возвращает количество позиций в корзине через свойство length массива;
 checkSelectedProduct(id: string): boolean — проверяет наличие товара с указанным id в корзине: true — найден, false — отсутствует.

#### Класс Buyer

Инкапсулирует данные покупателя и предоставляет методы для их управления: сохранения, получения, очистки и валидации с детализацией ошибок по каждому полю.

Конструктор:
constructor() — инициализирует объект покупателя с пустыми значениями всех полей.
Поля класса:
Объект, хранящий данные клиента: способ оплаты (payment), адрес (address), email (email) и телефон (phone).

Методы:
savePaymentType(payment: TPayment): void — обновляет способ оплаты в данных покупателя без изменения других полей;
saveAddress(address: string): void — сохраняет адрес доставки, не затрагивая остальные данные;
saveEmail(email: string): void — записывает email клиента, оставляя остальные поля без изменений;
savePhone(phone: string): void — фиксирует номер телефона, не меняя другие сведения;
getData(): IBuyer — возвращает полный объект с данными покупателя;
clearBuyerData(): void — сбрасывает все поля к пустым значениям, очищая информацию о клиенте;
validate(): {payment: string, address: string, email: string, phone: string} — проверяет корректность всех полей. Для каждого возвращает пустую строку (если валидно) или текст ошибки (если невалидно). Поле считается валидным, если после обрезки пробелов оно не пустое.

### Коммуникационный слой

#### Класс ServerApi

Реализует взаимодействие с сервером: получение и отправку данных. Использует композицию с классом Api для выполнения HTTP‑запросов.


Конструктор:
constructor(api: IApi) — принимает объект, соответствующий интерфейсу IApi.

Поле класса:
protected api: IApi — экземпляр, предоставляющий методы для отправки запросов на сервер.

Методы:
getProducts(): Promise<IResult> — выполняет GET‑запрос к эндпоинту /product/ и возвращает промис с объектом, содержащим массив товаров и общую стоимость;
postOrder(orderRequest: IOrderRequest): Promise<IOrderResponse> — отправляет POST‑запрос на эндпоинт /order/ с данными заказа и возвращает промис с результатом оформления.

### Cлой представления 

#### Класс Header
Компонент слоя Представления, отвечающий за визуализацию шапки веб‑страницы и обработку взаимодействий с пользователем. Основан на наследовании от класса Component для работы с DOM‑элементами.


Конструктор:
constructor(container: HTMLElement, protected events: IEvents) — получает:
container — DOM‑элемент‑контейнер, в котором размещается компонент;
events — объект, предназначенный для управления событиями интерфейса.

Поля класса:
protected basketButton: HTMLButtonElement — кнопка, которая запускает открытие корзины;
protected counterElement: HTMLElement — элемент интерфейса, показывающий количество товаров в корзине.

Генерируемые события:
shopping-cart:open — срабатывает при нажатии на кнопку корзины и инициирует её открытие.

Методы:
set counter(value: number) — обновляет значение счётчика товаров и отображает его в интерфейсе.


#### Класс Basket
Компонент слоя Представления для отображения и управления содержимым корзины товаров. Реализует наследование от класса Component с целью взаимодействия с DOM.

Конструктор:
constructor(container: HTMLElement, protected events: IEvents) — принимает:
container — контейнер DOM‑элемента корзины;
events — объект для управления событиями.

Поля класса:
protected basketListElement: HTMLElement — область отображения списка товаров, находящихся в корзине;
protected placeButton: HTMLButtonElement — кнопка, запускающая процесс оформления заказа;
protected priceElement: HTMLElement — элемент, отображающий итоговую стоимость товаров.

Генерируемые события:
order:open — активируется при нажатии на кнопку оформления и открывает форму заказа.

Методы:
set items(value: HTMLElement[]) — обновляет список товаров в корзине: отображает переданный массив элементов либо сообщение о том, что корзина пуста;
set price(value: number) — устанавливает общую стоимость заказа и отображает её в формате «X синапсов»;
setPurchaseOpportunity(isEmpty: boolean) — регулирует состояние кнопки оформления заказа: отключает и скрывает её, если корзина не содержит товаров.


#### Класс Gallery
Компонент слоя Представления, предназначенный для отображения галереи товаров в каталоге. Основан на наследовании от класса Component для управления DOM‑элементами.

Конструктор:
constructor(container: HTMLElement) — принимает container — контейнер, в котором будет отображаться галерея товаров.
Генерируемые события: отсутствуют, поскольку компонент выполняет функцию контейнера для карточек товаров.

Методы:
set catalog(items: HTMLElement[]) — очищает текущий контейнер и добавляет в него новые карточки товаров из переданного массива.


#### Класс Modal
Компонент слоя Представления для управления отображением и взаимодействием с модальными окнами. Наследует функционал класса Component.

Конструктор:
constructor(container: HTMLElement, protected events: IEvents) — получает:
container — контейнер модального окна;
events — объект управления событиями.


Поля класса:
protected closeButton: HTMLButtonElement — кнопка для закрытия модального окна;
protected contentElement: HTMLElement — область, предназначенная для отображения содержимого окна.


Генерируемые события:
modal:open — возникает в момент открытия модального окна;
modal:close — возникает при закрытии модального окна.

Методы:
set content(value: HTMLElement) — очищает текущее содержимое и устанавливает новый элемент в контейнер окна;
open(): void — открывает окно: добавляет класс modal_active и генерирует событие modal:open;
close(): void — закрывает окно: удаляет класс modal_active, очищает содержимое и генерирует событие modal:close.

#### Класс Success
Компонент слоя Представления, отображающий уведомление об успешном оформлении заказа. Основан на наследовании от базового класса Component.

Конструктор:
constructor(container: HTMLElement, actions: ISuccessActions) — получает:
container — контейнер для отображения сообщения об успехе;
actions — объект с обработчиками действий.

Поля класса:
protected orderButton: HTMLButtonElement — кнопка для закрытия уведомления об успешном заказе;
protected totalElement: HTMLElement — элемент, отображающий сумму списания.

Генерируемые события: не генерирует событий напрямую, выполняет переданный колбэк при клике.

Методы:
set total(value: number) — обновляет и отображает сумму списания в формате «Списано X синапсов».

constructor(container: HTMLElement) — принимает container — контейнер карточки товара.

Методы:

#### Класс CardPreview
Компонент слоя Представления для расширенного отображения карточки товара (режим предпросмотра). Расширяет Card, добавляя функционал для отображения описания, категории, изображения и кнопки действий.

Компонент слоя Представления для отображения и управления формой ввода контактных данных. Расширяет класс Form, добавляя поля для ввода email и номера телефона.

Конструктор:
constructor(container: HTMLFormElement, protected events: IEvents) — получает:
container — контейнер формы контактных данных (передаётся извне);
events — объект управления событиями интерфейса.

Поля класса (наследует поля базового класса: formElement, submitButton, errorsContainer):
protected emailElement: HTMLInputElement — поле формы для ввода email‑адреса пользователя;
protected phoneElement: HTMLInputElement — поле формы для ввода номера телефона пользователя.

Генерируемые события:
contacts:changed — генерируется при любом изменении данных в полях формы, передаёт объект с изменённым полем (email или phone) и его текущим значением;
contacts:submit — отправляется при успешной валидации и отправке формы (наследуется от базового класса Form).

Методы:
set email(value: string) — устанавливает значение в поле email: заполняет emailElement переданным адресом электронной почты;
set phone(value: string) — устанавливает значение в поле телефона: заполняет phoneElement переданным номером. Оба метода обеспечивают синхронизацию данных между внутренней логикой компонента и интерфейсом пользователя.

#### Класс Form
Абстрактный компонент слоя Представления, служащий базовым классом для всех типов форм. Основан на наследовании от Component для управления DOM‑элементами и определяет общую структуру формы.

Конструктор:
constructor(container: HTMLFormElement, protected events: IEvents) — принимает:
container — контейнер DOM‑элемента формы (передаётся извне);
events — объект управления событиями, используемый для координации взаимодействия с другими компонентами системы.

Поля класса:
protected formElement: HTMLFormElement — основной элемент формы, представляющий сам тег <form>;
protected submitButton: HTMLButtonElement — кнопка отправки формы (<button type="submit">), отвечающая за инициирование отправки данных;
protected errorsContainer: HTMLElement — контейнер для отображения сообщений об ошибках валидации (обычно элемент <div> с классом .form__errors).

Генерируемые события:
{formName}:submit — событие отправляется при успешной валидации формы и её отправке. Вместо {formName} подставляется атрибут name
формы (например, order:submit или contacts:submi).

Методы:
set valid(value: boolean) — управляет состоянием кнопки отправки:
если value равно true, кнопка активируется (становится кликабельной);
если value равно false, кнопка деактивируется (блокируется) и визуально выделяется как неактивная;
set errors(value: string[]) — отображает ошибки валидации:
принимает массив строк value, где каждая строка — отдельное сообщение об ошибке;
объединяет все сообщения в одну строку через запятую;
устанавливает полученную строку в errorsContainer, очищая предыдущие ошибки.

#### Класс OrderForm
Компонент слоя Представления для отображения и управления формой заказа. Расширяет базовый класс Form, добавляя функционал выбора способа оплаты и ввода адреса доставки.


Конструктор:
constructor(container: HTMLFormElement, protected events: IEvents) — получает:
container — контейнер формы заказа (передаётся извне, обычно с ID #order);
events — объект управления событиями интерфейса.

Поля класса (наследует formElement, submitButton, errorsContainer):
protected paymentButtons: HTMLButtonElement[] — массив кнопок для выбора способа оплаты (например, «Наличными», «Картой онлайн»);
protected addressElement: HTMLInputElement — поле ввода адреса доставки (<input name="address">).

Генерируемые события:
order:changed — возникает при изменении данных формы (выбор способа оплаты или ввод адреса), передаёт объект с полями:
payment — выбранный способ оплаты (строка);
address — введённый адрес доставки (строка);
order:submit — отправляется при успешной валидации и отправке формы (наследуется от базового класса Form).

Методы:
set payment(value: string) — устанавливает и визуально выделяет выбранный способ оплаты:
ищет в массиве paymentButtons кнопку, соответствующую переданному значению value;
добавляет к найденной кнопке класс button_alt-active, визуально отмечая её как выбранную;
удаляет класс button_alt-active у всех остальных кнопок в массиве, обеспечивая единообразный выбор (только один вариант активен);

set address(value: string) — заполняет поле ввода адреса (addressElement) переданным значением:
устанавливает свойство value элемента addressElement равным переданному параметру value;
обеспечивает синхронизацию между внутренней логикой компонента и отображаемым интерфейсом.

validate(): boolean — выполняет валидацию данных формы:
проверяет, выбран ли способ оплаты (хотя бы одна кнопка в paymentButtons имеет класс button_alt-active);
убеждается, что поле addressElement не пустое;
возвращает true, если оба условия выполнены, иначе — false;

getData(): { payment: string, address: string } — собирает и возвращает текущие данные формы:
определяет выбранный способ оплаты, анализируя состояние кнопок в paymentButtons;
извлекает значение из поля addressElement;
формирует и возвращает объект с полями payment и address.

reset(): void — сбрасывает форму к исходному состоянию:
очищает поле ввода адреса (addressElement.value = '');
снимает выделение со всех кнопок оплаты (удаляет класс button_alt-active из всех элементов paymentButtons);
деактивирует кнопку отправки формы (вызывает set valid(false));
 очищает контейнер ошибок (вызывает set errors([])).
