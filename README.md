# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

##### Данные

Данные в приложении деляться на две сущности: данные о товаре и информация о покупателе.

##### Интерфейс IProduct

Задаёт шаблон данных для описания товара в системе. Используется для отображения информации о продукте, доступном к приобретению. Включает все атрибуты, необходимые для идентификации позиции и предоставления пользователю сведений о её характеристиках, визуальном представлении и стоимости.

Поля интерфейса:

id: string — уникальное айди товара;
title: string — наименование товара, которое отображается в карточках каталога и в корзине;
image: string — путь к файлу изображения товара, используемый для его визуализации в каталоге и карточках;
category: string — категория, к которой принадлежит товар;
price: number | null — стоимость товара в числовом формате. Значение null указывает на отсутствие или недоступность цены.
description: string — развёрнутое описание продукта с подробной информацией о характеристиках;

##### Интерфейс IBuyer

Определяет структуру данных о клиенте приложения. Содержит сведения, требуемые для оформления покупки: способ оплаты, контактные данные и адрес доставки. Это позволяет корректно обрабатывать заказы и поддерживать связь с покупателем.

Поля интерфейса:

payment: 'card' | 'cash' — выбранный метод оплаты. Ограничен набором допустимых значений через два типа: card (безналичный) и cash (наличные);
address: string — адрес для доставки товара, указываемый пользователем при оформлении заказа;
email: string — электронная почта клиента, используемая для отправки уведомлений о заказе и связи с ним;
phone: string — номер телефона покупателя, необходимый для коммуникации по вопросам заказа и доставки.

###### Модели данных

##### Класс Products
Управляет массивом данных доступных товаров и отслеживает позицию, выбранную для детального просмотра. Предоставляет базовые операции для работы с каталогом.

Конструктор:

constructor() — инициализирует пустой массив для хранения товаров и переменную для выбранного товара (без аргументов).
Поля класса:

protected products: IProduct[] — массив всех товаров в каталоге;
protected selectedProduct: IProduct | null — товар, выбранный для подробного отображения.
Методы:

saveProducts(products: IProduct[]): void — сохраняет переданный массив товаров в модель каталога;
getProducts(): IProduct[] — возвращает полный список товаров из модели;
getProductByID(id: string): IProduct | undefined — ищет и возвращает товар по его идентификатору;
saveProduct(product: IProduct | null): void — сохраняет товар для подробного просмотра;
getProduct(): IProduct | null — возвращает выбранный для отображения товар.

##### Класс Basket
Хранит перечень товаров, отобранных покупателем для приобретения. Обеспечивает полный набор операций для управления корзиной: просмотр содержимого, добавление и удаление позиций, очистку, подсчёт суммы и количества, проверку наличия товара.

Конструктор:

constructor() — создаёт пустой массив для хранения выбранных товаров (без аргументов).
Поле класса:

protected selectedProducts: IProduct[] — список товаров в корзине покупателя.
Методы:

getSelectedProducts(): IProduct[] — возвращает все товары, находящиеся в корзине;
addSelectedProduct(product: IProduct): void — добавляет указанный товар в корзину;
deleteSelectedProduct(id: string): void — удаляет товар с заданным id из корзины (через фильтрацию);
clearShoppingCart(): void — очищает корзину, устанавливая пустой массив;
getTotal(): number — вычисляет и возвращает общую стоимость товаров в корзине (0 для пустой корзины или при отсутствии цен);
getSelectedProductsAmount(): number — возвращает количество позиций в корзине через свойство length массива;
checkSelectedProduct(id: string): boolean — проверяет наличие товара с указанным id в корзине: true — найден, false — отсутствует.

##### Класс Buyer
Инкапсулирует данные покупателя и предоставляет методы для их управления: сохранения, получения, очистки и валидации с детализацией ошибок по каждому полю.

Конструктор:

constructor() — инициализирует объект покупателя с пустыми значениями всех полей.
Поля класса:

Объект, хранящий данные клиента: способ оплаты (payment), адрес (address), email (email) и телефон (phone).
Методы:

savePaymentType(payment: TPayment): void — обновляет способ оплаты в данных покупателя без изменения других полей;
saveAddress(address: string): void — сохраняет адрес доставки, не затрагивая остальные данные;
saveEmail(email: string): void — записывает email клиента, оставляя остальные поля без изменений;
savePhone(phone: string): void — фиксирует номер телефона, не меняя другие сведения;
getData(): IBuyer — возвращает полный объект с данными покупателя;
clearBuyerData(): void — сбрасывает все поля к пустым значениям, очищая информацию о клиенте;
validate(): {payment: string, address: string, email: string, phone: string} — проверяет корректность всех полей. Для каждого возвращает пустую строку (если валидно) или текст ошибки (если невалидно). Поле считается валидным, если после обрезки пробелов оно не пустое.

##### Коммуникационный слой

#### Класс AppApi

Реализует взаимодействие с сервером: получение и отправку данных. Использует композицию с классом Api для выполнения HTTP‑запросов.

Конструктор:

constructor(api: IApi) — принимает объект, соответствующий интерфейсу IApi.
Поле класса:

protected api: IApi — экземпляр, предоставляющий методы для отправки запросов на сервер.
Методы:

getProducts(): Promise<IResult> — выполняет GET‑запрос к эндпоинту /product/ и возвращает промис с объектом, содержащим массив товаров и общую стоимость;
postOrder(orderRequest: IOrderRequest): Promise<IOrderResponse> — отправляет POST‑запрос на эндпоинт /order/ с данными заказа и возвращает промис с результатом оформления.
